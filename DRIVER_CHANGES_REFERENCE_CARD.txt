║ RULE #1: Move Driver Initialization to Task Startup                           ║
╚════════════════════════════════════════════════════════════════════════════════╝

❌ WRONG - Bare-Metal Style:
─────────────────────────────────────────────────────────────────────────────────
  int main(void) {
      motor_driver_init();      ← Driver init in main
      imu_driver_init();
      line_following_init();
      
      multicore_launch_core1(vc_core);  ← Explicit core launch
      obs_core();
  }

✅ CORRECT - RTOS Style:
─────────────────────────────────────────────────────────────────────────────────
  // In motion_control_task.c
  void motion_control_task(INT stacd, void *exinf) {
      motor_driver_init();      ← Driver init inside task
      motor_driver_mutex_init();
      motion_control_init();
      
      for (;;) {
          // ...
          tk_dly_tsk(10);       ← RTOS-safe delay
      }
  }

  // In imu_task.c
  void imu_task(INT stacd, void *exinf) {
      imu_driver_init();        ← Driver init inside task
      imu_processor_init(&state);
      
      for (;;) {
          // ...
          tk_dly_tsk(50);
      }
  }


╔════════════════════════════════════════════════════════════════════════════════╗
║ RULE #2: Replace sleep_ms() with tk_dly_tsk()                                 ║
╚════════════════════════════════════════════════════════════════════════════════╝

Context                       ❌ WRONG              ✅ CORRECT
─────────────────────────────────────────────────────────────────────────────
In device init function       sleep_ms(10);         sleep_ms(10);  ← OK
(called once at boot)                               (boot-time only)

In task main loop             sleep_ms(10);         tk_dly_tsk(10);
(called repeatedly)           (blocks RTOS)         (yields to scheduler)

In interrupt handler          ❌ NOT ALLOWED        ❌ NOT ALLOWED
(ISR context)                 sleep_ms(x);          No delays in ISR!


╔════════════════════════════════════════════════════════════════════════════════╗
║ RULE #3: Protect Motor State with Mutex                                        ║
╚════════════════════════════════════════════════════════════════════════════════╝

ADD TO motor_driver.c:
─────────────────────────────────────────────────────────────────────────────
  // Global: protects motor state from concurrent access
  static ID s_motor_mutex = NULL;

  // Call once at task startup
  void motor_driver_mutex_init(void) {
      T_CMTX config = {0};
      config.mtxatr = TA_TFIFO;
      s_motor_mutex = tk_cre_mtx(&config);
  }

WRAP EVERY MOTOR FUNCTION:
─────────────────────────────────────────────────────────────────────────────
  void motor_set_speed(motor_id_t motor, int16_t speed_percent) {
      if (s_motor_mutex != NULL) {
          tk_loc_mtx(s_motor_mutex, TMO_FEVR);  ← LOCK
      }
      
      // ... existing motor control code ...
      
      if (s_motor_mutex != NULL) {
          tk_unl_mtx(s_motor_mutex);            ← UNLOCK
      }
  }

FUNCTIONS THAT NEED MUTEX:
  ✓ motor_set_speed()
  ✓ motor_brake_all()
  ✓ motor_emergency_stop()
  ✓ motor_clear_emergency_stop()
  ✗ motor_is_emergency_stopped()  (read-only, no mutex needed)

╔════════════════════════════════════════════════════════════════════════════════╗
║ TOP 5 MISTAKES AND HOW TO AVOID THEM                                           ║
╚════════════════════════════════════════════════════════════════════════════════╝

#1: Calling motor_driver_init() in main()
    Problem: Task init conflicts, double initialization
    Prevention: Call only inside motion_control_task()
    Test: Compile and check: "motor_driver_init" should NOT appear in car_main.c

#2: Using sleep_ms() in task loops
    Problem: Blocks entire RTOS scheduler, other tasks starve
    Prevention: Replace with tk_dly_tsk()
    Test: Grep: grep -n "sleep_ms" src/motion_control_task.c
          Should show 0 matches in loop, OK if in init

#3: Not protecting motor state with mutex
    Problem: Race condition, concurrent motor commands cause crash
    Prevention: Add tk_loc_mtx() / tk_unl_mtx() wraps
    Test: Run with multiple tasks sending motor commands simultaneously

#4: Forgetting to include <tk/tkernel.h>
    Problem: Compilation errors, undefined references
    Prevention: Add at top of all task files
    Test: Compiler should find tk_dly_tsk, tk_loc_mtx, etc.

#5: Keeping multicore_launch_core1()
    Problem: Conflicts with RTOS task scheduler
    Prevention: Remove from car_main.c
    Test: Compile and grep: grep -n "multicore_launch" car_main.c
          Should show 0 matches
